# PaperMorrow Research Cowork — 下一窗口开发提示词

继续开发 `/Users/yuzihang/Downloads/ace-deepwiki-main` 中的 PaperMorrow。请把“AI 协作”实现为面向科研人员的本地优先桌面 Cowork Agent，而不是普通聊天页，也不要重写现有 PaperMorrow。

## 开始前必须完成

1. 阅读项目的 `AGENTS.md`（如有）、`.gitignore`、现有 API/模型/笔记/项目/实验/PPT/DeepWiki 实现和最近提交。
2. 不得删除、重置、批量改写用户数据库、API Key、论文、PDF、笔记、Wiki、项目、实验和历史记录。数据库变更必须备份、增量迁移、独立回退。
3. 先为当前状态建立 Git 检查点。每个阶段单独提交；每阶段运行后端测试、前端正式构建和真实浏览器检查。
4. 保持 Apple 风格深浅色、本地优先和单机架构。不要引入独立向量数据库、Kubernetes 或不必要的微服务；检索优先 SQLite FTS5/BM25。
5. 参考而不照搬成熟实现：Coworker/Accomplish 的本地文件夹授权、长任务与审批日志；MCP 官方协议的工具边界；Anthropic Agent Skills 的按需加载结构及文档类技能；腾讯 WorkBuddy 等桌面产品的自然语言任务入口。检查许可证，禁止复制不兼容代码。

## 产品目标

建立类似 Codex/Claude Desktop Cowork 的独立工作区，但围绕科研收敛：用户提出目标，选择文件或文件夹，明确资料权限和操作权限；Agent 形成可编辑计划，检索最小必要上下文，调用 PaperMorrow 内置能力或受控工具，持续展示进度、来源、待审批操作和产物。页面级“问 AI”复用同一会话与消息组件，但只能读取当前可见页面，没有文件夹选择和思考强度；两者都支持简洁/丰富回答、附件、逐段存入笔记和论文一键导入。

## 架构边界

在现有后端内新增清晰模块，不另起大型服务：

- `CoworkSession`：标题、目标、状态、模型配置、回答详细度、思考强度、创建/更新时间。
- `CoworkMessage`：角色、结构化内容块、来源、附件、工具调用、审批引用和 Token 用量。
- `CoworkTask` / `CoworkStep`：可编辑计划、依赖关系、状态、重试、检查点和结果摘要。
- `PermissionGrant`：资源类型、规范化路径或 PaperMorrow 对象范围、读/写权限、会话/永久期限、授予时间和撤销状态。
- `ToolCall`：工具名、参数摘要、风险级别、审批状态、开始/结束时间、结果、错误和可撤销线索。
- `CoworkArtifact`：生成文件、笔记、PPT、报告、表格、导入论文等产物及来源关系。
- `SkillManifest`：name、description、version、入口、允许工具、来源、许可证、启用状态和校验信息。

所有持久化使用增量 SQLite 迁移。大文件仍放本地文件系统，只在数据库保存受控引用。对话历史不得无上限塞入模型：使用最近消息、任务状态摘要、用户选定资料和 FTS 检索片段组成上下文，并保留来源编号。

## 内置 PaperMorrow MCP / Tool Registry

建立稳定的内部工具接口，再按需暴露为本地 MCP；业务代码不得依赖具体模型：

- 搜索/读取学习库论文、元数据、摘要、允许的 PDF 片段和证据化分析。
- 将 DOI、arXiv URL、标题或结构化元数据导入学习库，导入前预览并永久去重。
- 搜索、读取和在获得授权后追加/创建 Markdown 笔记；任何覆盖必须单独审批。
- 搜索、读取当前授权项目、实验记录、专题调研和 DeepWiki；严禁默认读取全部用户资料。
- 创建/更新待办和 DDL；写操作展示预览。
- 创建可编辑 PPT 大纲、生成 PPT、PDF、DOCX、XLSX 和 Markdown 报告；输出进入会话产物区。
- 在项目中增加论文、笔记、实验或产物关联，必须保留来源和用户确认。
- 文件工具只允许在用户选择的根目录中工作；规范化真实路径，阻止 `..`、符号链接逃逸、隐藏密钥读取和越权写入。

工具参数使用严格 schema，返回结构化结果与用户可读摘要。工具说明中的外部文本一律视为不可信数据，防止 prompt injection。不得向模型发送 API Key、`.env`、密钥文件或未授权隐藏文件。

## 权限与审批

采用默认拒绝和最小权限：

- 读取 PaperMorrow 当前页可自动允许；读取笔记/项目/阅读记录/文件夹需用户授权。
- 新建可恢复的草稿可“本次允许”；修改现有文件、批量导入、移动文件或外部请求必须预览。
- 删除、覆盖、执行脚本、安装依赖、Git 写操作和向外部服务上传内容必须逐次确认，不提供“永久允许删除”。
- 审批卡展示：将做什么、影响哪些对象、为什么需要、可否撤销、发送到哪个外部模型/服务。
- 支持立即停止任务、撤销授权、清除会话上下文；停止后不得留下后台 Agent。
- 工具结果和审批写入审计日志，但日志不得保存密钥和完整敏感文件。

## Agent Runtime

实现可测试的单 Agent 主循环加可选专家委派，不先做失控的多 Agent 群：

1. 理解目标并识别缺失信息。
2. 生成 3–8 步可编辑计划；简单问题可直接回答。
3. 为下一步选择最小上下文与工具。
4. 在需要时请求权限/审批。
5. 执行一个步骤，验证结果，再继续。
6. 失败时说明原因，最多有限重试；不得静默扩大范围。
7. 结束时汇总完成项、产物、来源、未完成项和建议下一步。

支持暂停、继续、取消、重试单步和从检查点恢复。模型提供方沿用现有 LLM Profile；能力检测决定是否支持工具调用和更高思考强度。无原生 tool calling 时使用经过 schema 校验的 JSON 适配器，禁止执行模型生成的任意代码。

专家角色按需启用：文献检索与证据核验、实验分析、笔记与综述、PPT/文档、项目规划。专家只能获得主 Agent 分配的最小资料和工具，并把结构化结果返回主 Agent；不要把全库内容复制给每个 Agent。

## Skills

实现懒加载的 Skill 目录和清晰清单，预装少量高价值科研 Skill：

- 文献检索与保守去重。
- 论文精读与证据定位。
- 系统综述/专题调研（结论必须追溯论文）。
- 实验记录比较与异常检查（事实引用实验编号）。
- 组会论文汇报、研究进度汇报 PPT。
- Markdown/论文到 DOCX、PDF、XLSX 数据表。
- 引用检查、研究计划、复现准备清单。

参考成熟文档技能的“说明 + 脚本 + 资源 + 验证”结构，但只引入许可证允许且经过本地安全审查的内容。技能安装必须展示来源、许可证、版本、声明的工具和权限；默认不允许技能联网、执行 shell 或读取未授权目录。不要为了数量预装大量低质量 Skill。

## UI

左侧“AI 协作”进入独立页面：

- 中央任务输入区，支持拖入文件、选择文件夹、引用论文/笔记/项目。
- 输入区提供模型、简洁/丰富、思考强度；普通页面“问 AI”不显示文件夹和思考强度。
- 对话顶部显示当前授权范围，随时可调整或撤销。
- 会话中呈现可编辑计划、运行步骤、工具调用、审批卡、来源和产物，不展示冗长内部推理。
- 论文识别卡支持预览后“一键导入学习库”；不得只凭标题自动导入。
- 每段 AI 回复都能新建或追加到笔记，并保留会话来源。
- 文件与产物侧栏支持预览、打开所在位置、关联项目。
- 全局 AI 浮窗继续支持拖动、全屏和恢复；位置不能超出屏幕，窗口缩放后自动校正。
- 深浅色、桌面与窄屏完整适配；键盘可访问，审批不能依赖颜色区分。

## 科研可信度

- 回答必须区分论文事实、作者主张、用户记录和 AI 推断。
- 引用论文内容时使用 PaperMorrow 已有证据来源；只有摘要时标明“仅摘要”。
- 不伪造 DOI、页码、实验数值、会议 DDL、期刊指标或工具执行结果。
- 网络检索结果先进入候选预览，展示来源与时间；用户确认后才能写入库或项目。
- 临床医学继续遵守证据等级、预印本风险和研究设计规则。

## 测试与交付顺序

按以下阶段连续实现并分别提交：

1. 数据模型、迁移备份、权限模型和审计日志。
2. 内部 Tool Registry 与 PaperMorrow 核心工具的 mock/契约测试。
3. Cowork 会话、计划、有限工具循环、暂停/恢复/取消。
4. 文件/文件夹授权与路径逃逸安全测试。
5. 科研 Skills 与 PPT/文档产物接入。
6. 完整 Cowork UI、页面助手共用组件和论文导入卡。
7. 真实浏览器检查、公开无数据副本、macOS/Windows 构建配置。

验收至少覆盖：迁移保留旧数据；未授权读取被拒绝；符号链接与路径穿越被拒绝；危险操作触发审批；取消后任务停止；重启后可恢复；工具 schema 错误不会执行；prompt injection 不会改变权限；无 API Key 可靠降级；网络全部 mock；后端全测、前端正式构建、深浅色/桌面/窄屏真实浏览器均通过。不要在测试中读取真实用户笔记或调用真实网络。

完成后报告各提交、测试、已知限制和回退位置；不要声称尚未验证的模型、技能或 Windows 安装包已经可用。

# PaperMorrow

PaperMorrow 是一个本地优先的科研工作台，将论文发现、证据化阅读、研究项目、实验记录、学习笔记与 DeepWiki 代码知识库连接为一条可追溯的研究流程。Domain Pack 为人工智能、计算机、物理、数学、生命科学、临床医学、化学与材料、经济学与金融提供各自的数据源和评价体系。

## 已实现功能

- 同时支持广度推荐、研究方向聚焦推荐，以及“聚焦 + 探索”混合推荐，可指定每批篇数。
- 研究方向支持自然语言描述、正负关键词、种子论文，以及关联度／时效性／探索比例调节。
- AI 方向包含 LLM、Agent、Harness、自进化模型、测试时学习、推理、长上下文与记忆等细分标签；并提供计算机、物理和数学领域标签。
- AI 方向优先 CCF-A 和同级顶会顶刊；物理、数学采用各自领域顶刊信号，并保留前沿 arXiv 预印本探索位。
- 数据库永久记录历史推荐，同一论文不会再次进入推荐批次。
- 英文标题始终显示；中文标题作为补充。
- 中英文摘要按钮切换，默认中文，可在设置中改为默认英文。
- AI 生成中文摘要、研究问题、方法、创新点、价值与局限。
- 推荐历史与学习库使用按需展开：折叠时保留代码仓库／DeepWiki 入口，展开后显示与推荐页一致的完整论文分析；缺少分析时才调用模型补全。
- 多路召回后由 LLM 扩展研究语义，并对创新性、研究价值、可信度、方向关联度和阅读品味复排。
- 每篇聚焦推荐显示方向关联度、匹配概念、置信度、推荐理由和聚焦／相邻／探索来源。
- “专题调研”允许选择 AI、计算机、物理或数学领域并输入自然语言问题；LLM 自动扩展检索语义，聚合 arXiv 与 Semantic Scholar，按关联度、价值、创新性和置信度综合排序。
- 调研结果支持逐篇“展开 AI 详情”，按需显示中英文摘要、研究问题、方法、创新、价值、局限和适读人群，再决定是否加入学习库。
- 专题调研支持一键生成带 `[P1]` 引用标记的中文文献综述；调研发现过的论文也进入永久去重集合，不会再被普通推荐重复推送。
- 专题调研还能生成带论文引用和“AI 推断”标记的研究分类体系、论文对比表、主要路线、代表工作、争议与研究空白，并可关联研究项目。
- “研究项目”统一管理研究问题、论文角色、六种阅读状态、项目笔记、代码仓库、DeepWiki、当前结论、待解决问题和下一篇阅读建议；项目 AI 仅检索当前项目，使用 SQLite FTS5/BM25，不引入独立向量数据库。
- 项目实验记录支持实验时间线、指标变化、产物归档和结果汇总；实验分析助手基于当前项目的完整实验过程给出带记录来源的观察与下一步建议。
- 学习笔记统一归档阅读器笔记与独立笔记，支持 Markdown、LaTeX、可视化常规编辑和纯源码专业编辑，并可绑定多篇论文、生成流程图或思维导图。
- 演示文稿先生成可编辑大纲供用户审核，也可从空白大纲开始；每一页都能手动引用笔记、论文和实验记录，再生成可继续编辑的 `.pptx`。
- Domain Pack 将学科评价体系与具体研究方向分离；内置八个专业，并支持数据源、Venue、论文类型、评分、证据规则、自定义指标、搜索预览、启停、导出和导入。
- 数据源适配器覆盖 arXiv、Semantic Scholar、OpenAlex、Crossref、PubMed、Europe PMC 和 RSS/Atom；普通网站 URL 不会触发通用网页爬虫。
- 论文分析区分全文、摘要和作者声明，并把研究问题、方法、创新、实验结论与局限绑定到章节、短证据片段和结论类型；仅摘要分析绝不生成页码。
- 论文 Work/Version 时间线使用 DOI、arXiv 主标识、Crossref 关系、标题和作者做保守匹配，低置信度需确认，并支持拆分和撤销。
- 可保存多个模型 API 并随时切换当前接口，支持 OpenAI、Claude、GLM、DeepSeek、智增增预设和任意 OpenAI 兼容地址。
- Token 用量按今日、累计、API、用途和日期统计；接口不返回 usage 时自动给出带标记的近似估算。
- 智能 PDF 阅读器支持左侧论文、右侧 Chat／笔记／双栏模式；长论文按视口附近懒渲染。
- 可选择 PDF 原文进行精确翻译、问 AI 或引用到笔记，也可框选论文插图并插入 Markdown 笔记。
- 可在阅读器中和 AI 连续对话，会话永久保存，并自动携带摘要、全文、AI 分析和学习笔记上下文。
- Apple 风格响应式界面，支持深色、浅色主题并记忆选择；全局字号可在 13–20px 间调节，主页面、智能阅读器与 DeepWiki 统一缩放。完整 Wiki 顶栏也常驻显示 A−／滑杆／A+ 控件，无需退出阅读页面。
- 相关研究查询。
- GitHub 开源仓库自动发现与手动绑定 API。
- 一键启动 DeepWiki 源码研究 Agent，不执行第三方仓库代码；恢复原项目的 ReAct 图、检索工具、研究记事本、任务清单、目录 Schema 和逐页写作规范。
- 可从本地记录、arXiv 与 Semantic Scholar 搜索论文并主动纳入学习库。
- 学习库支持一篇论文多个个人标签、组合筛选、学习完成标记、Markdown 笔记、实时预览和自动保存。
- 学习库支持映射一个真实本地根目录并建立多级文件夹；直接放入 PDF 后后台约每两分钟自动扫描，也可手动立即扫描，不移动或改写原文件。
- 本地 PDF 会按 DOI、arXiv ID、标题指纹和文件哈希去重，自动加入学习库并计入“已发现论文”，之后不再推荐。
- 证据化知识图谱支持论文、方法、任务、数据集、Benchmark、模型、实验结论、局限、仓库、权重和项目；关系必须保存来源、证据与置信度，不默认生成“语义相似”边。
- 论文可登记官方仓库、第三方复现、模型权重、数据集和项目主页；完整 DeepWiki 生成后自动建立复现准备清单，状态严格限制为已确认、可能一致、缺失或无法确认。
- 可将学习库论文的标题、作者、摘要、DOI／arXiv ID、个人标签和可选 Collection 同步到 Zotero。
- 每日推荐默认关闭，可选择北京时间、美东时间、美西时间。
- 应用启动补跑错过的每日任务。

## 一键启动

### macOS / Linux

```bash
chmod +x start.sh
./start.sh
```

### Windows

双击 `start.bat`，或在终端运行：

```bat
start.bat
```

首次启动会安装依赖并构建前端，之后访问：

```text
http://127.0.0.1:8000
```

API 文档：

```text
http://127.0.0.1:8000/docs
```

## macOS / Windows 桌面应用

项目已经提供原生桌面窗口封装，前端、后端与本地数据库会随应用一起启动，不再需要手动打开终端或浏览器。桌面版数据与安装包分离：macOS 保存在 `~/Library/Application Support/PaperMorrow`，Windows 保存在 `%APPDATA%\PaperMorrow`。

- 本机 macOS 构建：先安装 `requirements-desktop.txt`，再运行 `bash scripts/build_macos_app.sh`；产物为可拖入“应用程序”的 `desktop_dist/PaperMorrow-macOS.dmg`。
- Windows 构建：在 Windows PowerShell 运行 `scripts/build_windows_app.ps1`；产物为可双击安装的 `desktop_dist\PaperMorrow-Windows-Setup.exe`，并同时提供免安装便携压缩包。
- GitHub Actions 中手动运行 `Build desktop apps`，可同时获得 macOS 与 Windows 构建产物。

签名、公证、Windows 安装器和具体构建环境要求见 [DESKTOP_BUILD.md](DESKTOP_BUILD.md)。

## 配置模型

应用不配置模型也能启动、推荐论文、保存笔记和解析基础代码结构。中文摘要和 AI 深度分析会显示“等待配置”。

推荐直接在“设置 → 模型 API”中添加一个或多个接口，填写名称、Base URL、模型名称和 API Key，再点击所需配置将它设为当前接口。推荐复排、中文分析、论文对话与 DeepWiki 会共同使用当前接口。Key 只保存到本机 `data/secrets.json`，接口不会将其返回前端。

也可以复制环境变量模板：

```bash
cp .env.example .env
```

支持的模型协议：

| 服务商 | 默认 Base URL | 默认模型 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` |
| Claude | `https://api.anthropic.com/v1` | `claude-sonnet-4-5` |
| GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.5` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智增增（自定义中转预设） | `https://api.zhizengzeng.com/v1` | `gpt-4.1-mini`（可修改） |
| 自定义 OpenAI 兼容 API | 用户填写 | 用户填写 |

模型名称和地址均可修改，以服务商当前实际提供的模型为准。Base URL 既可填写 `/v1` 根地址，也可直接填写完整的 `/chat/completions` 地址。

## Token 统计

“设置 → Token 用量”提供：

- 当日与累计 Token，总输入、总输出和请求次数。
- 按当前保存的 API 配置拆分。
- 按推荐复排、摘要分析、论文翻译、论文对话、DeepWiki 拆分。
- 最近有用量日期的趋势。
- 对未返回标准 `usage` 字段的中转接口使用字符量估算，并单独标记估算请求数。

统计时间遵循设置中的北京时间、美东时间或美西时间。历史用量保存在本地数据库，删除某个 API 配置不会删除它已有的统计记录。

## 推荐模式与规则

1. “广度推荐”按所选 Tag 发现领域内近期高价值研究，适合保持视野。
2. “方向聚焦”从自然语言描述、正负关键词和种子论文生成检索语义，进行聚焦召回与方向关联度判断。
3. “聚焦 + 探索”按研究方向的探索比例保留高质量相邻论文，避免兴趣越用越窄。
4. 基础质量分默认由新鲜度 40%、Venue 35%、Tag 相关度 20%、代码开放信号 5% 组成。
5. 候选会交给 LLM 评估 taste、创新性、研究价值、语义关联度、置信度和潜在风险；未配置或调用失败时自动降级为本地规则。
6. 聚焦模式使用每个研究方向独立设置的关联度和时效权重；剩余权重用于学术质量，探索比例单独控制阅读列表中的探索位。
7. 广度模式默认目标为 70% 已核验顶会顶刊、30% 最新预印本；可启用“仅推荐已核验顶会顶刊”。
8. 去重优先使用 DOI、arXiv ID、Semantic Scholar ID，最后使用标准化标题指纹；推荐记录永久去重。

## 智能 PDF 阅读器

论文卡片中的“阅读论文”会进入专注阅读界面：左侧显示原始 PDF，右侧可以选择 Chat、Markdown 笔记，或二者同时显示。

- 拖选 PDF 文字后可翻译为中文、直接向 AI 提问，或把原文与翻译引用到笔记。
- “框选插图”会从当前 PDF 页面 Canvas 裁取图片，安全保存到本地，并自动写入 Markdown 图片引用。
- PDF 页面只在视口附近渲染，避免长论文一次性占用大量浏览器内存。
- 笔记实时预览、自动保存；关闭阅读器前会再次显式保存。
- 阅读器不修改 PDF，不保存 PDF 涂改或高亮痕迹，也不提供跨设备同步。

## 论文 AI 对话

论文卡片中的“和 AI 讨论”会打开右侧对话面板。对话上下文包含：

- 英文标题和中英文摘要
- 作者、Venue 和论文链接
- 已生成的论文创新点与价值分析
- 你的 Markdown 学习笔记
- 当前会话最近 20 条消息
- 可公开访问的 arXiv PDF 正文（最多 25MB、100 页、18 万字符，首次提取后缓存）

系统优先使用公开全文；获取或提取失败时降级到摘要，并要求模型明确说明上下文限制。对话支持多个会话和历史恢复。

## 专题调研与一键综述

“专题调研”面向一个明确问题而不是固定 Tag。系统先让当前 LLM 提取核心概念和最多五组检索语义，再并行查询 arXiv 与 Semantic Scholar、合并重复论文，并综合计算关联度、研究价值、创新性、可信度、Venue 与时效性。结果会显示各项分数、排序理由和风险提示；点击“展开 AI 详情”会读取已有的完整论文分析，缺失时才调用当前模型生成，随后可以据此决定是否加入学习库。

“一键生成综述”只使用当前结果中的标题、作者、Venue 和摘要，要求模型用 `[P1]`、`[P2]` 等标记引用来源，并明确摘要证据的局限。综述与调研记录保存在本地数据库；调用会使用当前所选模型 API 并计入 Token 统计。

## 每日推荐

每日推荐默认关闭。开启前需要配置：

- 推荐时间
- 北京时间 / 美东时间 / 美西时间
- 每日篇数
- 至少一个研究 Tag

程序需要处于运行状态才能准时执行。如果设定时间已过且当天漏跑，下一次启动会补跑一次。

## DeepWiki 安全边界

- 目前只允许 HTTPS GitHub 仓库。
- 使用浅克隆并限制单文件、总读取量和任务时长。
- 忽略依赖、构建产物、模型权重、数据集和二进制文件。
- 不安装依赖，不运行脚本，不执行仓库代码。
- DeepWiki 必须使用当前模型 API 完整运行原项目的 ReAct 研究图与工具链；未配置密钥时会明确阻止启动，不再用三页静态结果冒充生成成功。
- 目录严格采用原项目 Schema，必须包含分区和至少 8 个主题页；每一页都会在独立研究上下文中重新使用文件树、代码大纲、分段读取、文件内搜索、目录搜索、任务清单和研究记录工具。
- 页面遵循原项目输出模式：开头列出最多 5 个相关源文件（小仓库按真实文件数量验收）、源码行号引用、H1/H2/H3 教程结构、模块关系与设计理由、竖向 Mermaid 图、必要的表格与短代码片段。内容不够深入时会自动再次研究和重写。
- 若兼容接口在研究轮次结束时返回序列化工具调用，系统会用已积累的研究记事本进入无工具终稿阶段，再按逐页质量清单定向修订，避免把 DSML／XML 工具指令误当作 Wiki 正文。
- Wiki 写入前会逐页检查正文，并使用临时目录原子替换；目录或任意页面不满足质量约束时整项任务失败，旧 Wiki 保持不变。
- Wiki 使用完整工作区展示：先进入分区目录首页，再进入带分组侧栏、源码链接、图表、长正文和前后页导航的独立阅读页。
- Mermaid 图会按当前内容宽度与视口高度保持比例自动缩放，完整显示且不再产生图内横向滚动。

原有的简版 Wiki 不会自动消耗 Token 重建，并会在任务页明确标记为“旧版简化”。补全当前模型 API Key 后点击“重新生成”，才会按上述完整流程生成新的丰富版本；一次任务包含一次目录研究和多个页面研究调用，Token 消耗会明显高于普通论文摘要。

## 学习库、本地文件夹与 Zotero

“学习库”是本应用的论文整理中心。除主动搜索收录外，在推荐页写笔记或标记学习完成也会自动收录。推荐系统 Tag 与个人整理 Tag 分开保存，避免修改推荐逻辑；个人 Tag 可多选，并支持多个 Tag 交集筛选。

学习库顶部可以设置本地知识库根目录。网页内创建文件夹时会同步创建真实目录；也可以在 Finder／文件管理器中自行建立任意层级并放入 PDF。系统后台约每两分钟巡检一次，或点击“立即扫描”马上同步。扫描只读取文件元数据与前几页文本，不移动、修改或删除 PDF；文件被移走后记录会标记为缺失。论文笔记可使用 `[[另一篇论文标题]]` 建立关系，并在“知识关系”视图中查看文件夹、Tag、论文和概念节点。

推荐历史和学习库卡片默认折叠，便于浏览大量论文。点击“展开详情”只读取已有分析；当卡片显示“展开并生成分析”时才会调用当前模型，并计入 Token 统计。无论是否展开，都可以直接查找代码仓库或启动 DeepWiki。

Zotero 连接位于“设置 → Zotero”。默认采用元数据同步：

- 同步英文标题、作者、英文摘要、论文链接、日期、DOI、arXiv ID 和 Venue。
- 自动添加 `PaperMorrow` 标签，并可选择同步学习库中的个人 Tag。
- 可填写 Zotero Collection Key，将论文统一放进指定 Collection。
- 再次同步会更新同一条目；系统优先通过 DOI／arXiv ID 查找已有条目，减少重复。
- 当前不会自动上传 PDF，也不会在“解除关联”时删除 Zotero 远程条目，避免意外覆盖用户已有附件和整理结果。

需要在 Zotero 账户中创建具有文献库写权限的 Web API Key，并填写个人 Library ID；团队文献库可切换为 Group 并填写 Group ID。

Presentation Studio 使用严格的内容模型与固定学术版式生成可编辑 PowerPoint。模型只负责证据选择、叙事与大纲，不直接控制坐标或 PowerPoint XML；未配置模型时仍可使用本地大纲和固定模板完成核心流程。

测试：

```bash
.venv-paper/bin/python -m pytest
```

## 数据与隐私

论文历史、学习状态、笔记和 Wiki 都保存在本机 `data/`。删除该目录会清除本应用数据，请在需要时自行备份。
